01

Что понадобится

Docker сам установит Python, Node.js и остальные зависимости в контейнеры. Поэтому первый запуск займёт больше времени, чем последующие.

02

Скачать проект

Эти команды скачают проект и выберут версию, указанную в сданном решении. Данные из архива добавляются в эту же копию проекта.

03

Загрузить кешированные данные

В архиве собран полный комплект данных для запуска: новости, аналитика банка, эмбеддинги, ответы моделей и готовые карточки. Перенесите его в проект целиком, чтобы после запуска сразу открыть подготовленную ленту.

  1. Откройте архив с данными в Google Диске и нажмите «Скачать».
  2. Распакуйте скачанный архив на компьютере. Внутри находятся папки data, backend и stage5_insight_detection.
  3. Перенесите всё содержимое архива в папку проекта и замените все совпадающие файлы.
  4. Сверьтесь со структурой ниже. Путь должен быть alfafuture/data/…, а не alfafuture/alfafuture-data/data/….

04

Настроить .env

Создайте файл .env в папке common/llm и вставьте в него текст ниже. В качестве LLM_API_KEY укажите свой ключ. Проверьте, что файл называется именно .env, а не .env.txt.

Вставьте в файл common/llm/.env 
# api ключ нашей команды 
LLM_API_KEY=your_team_key
LLM_BASE_URL=https://changellenge.up.railway.app/v1
AGENT_MODEL=z-ai/glm-5.3-flash
CHEAP_MODEL=google/gemma-4-26b-a4b-it
VISION_MODEL=qwen/qwen3-vl-30b-a3b-instruct

В примере указан API, который использовала команда. Если используете другой сервис, замените его адрес, ключ и названия моделей.

05

Запустить

Откройте терминал в папке проекта, выберите свою систему и выполните команды по порядку:

Windows PowerShell 
$env:CABINET_MODE='full'
docker compose up -d redis
docker compose run --rm pipeline python -X utf8 scripts_seed_redis.py
docker compose up -d --build
docker compose ps
Linux / macOS 
export CABINET_MODE=full
docker compose up -d redis
docker compose run --rm pipeline python -X utf8 scripts_seed_redis.py
docker compose up -d --build
docker compose ps

Команда scripts_seed_redis.py загрузит сохранённые ответы моделей и другие кеши из data в Redis. Новый анализ при этом не запускается. В первый раз Docker также соберёт контейнер pipeline.

Когда контейнеры запустятся, откройте http://localhost:5173. В выводе docker compose ps должны быть запущены четыре сервиса: redis, backend, feedback-api и frontend.

Используйте режим full, чтобы работали чаты и новый анализ. В режиме server они отключены. Если проект уже работал в этом режиме, выполните команды выше заново: они включат full и пересоберут приложение.
06

Проверить

  1. Готовая лента. Откройте раздел «Инсайты». В нём должны появиться закешированные результаты работы — заново запускать анализ не обязательно.
  2. Источники. Откройте карточку и проверьте ссылки на статьи, данные компании и фрагменты отчётов.
  3. Чаты. Задайте вопрос по инсайту, у которого есть источники. Затем проверьте «Чат с банком». Для ответов нужен доступ к API.
  4. Данные компании. Проверьте профиль, список контрагентов и платёжную аналитику. Эти разделы загружают данные из CSV в папке data.
  5. Новые документы и анализ. Чтобы дополнить обработку своей собственной аналитиклй, загрузите PDF через документооборот или запустите анализ компании. Для просмотра готовых инсайтов этот шаг можно пропустить.

07

Если не работает

Карточек мало или осталась только аналитика банка

Проверьте, что файлы с готовыми результатами скопированы в data/api/analyses/*.json именно той копии проекта, которую вы запускаете. Приложение читает их при старте: выполните docker compose restart backend и обновите страницу. Если скопировать только кеш ответов моделей, карточки в ленте не появятся.

Не найдены таблицы, компания или аналитика

Проверьте, что скопированы все три CSV, папки data/api/bank и data/analytics. Убедитесь, что при распаковке не появилась лишняя папка data/data. Выбранная компания должна быть в таблицах из архива.

Docker не может подключить common/llm/.env

Проверьте путь common/llm/.env: там должен быть текстовый файл с настройками API. Если вместо него появилась папка, удалите эту пустую папку, создайте файл и повторите запуск.

Чат или анализ не отвечает

Убедитесь, что включён режим full, ключ указан верно, а сервис API доступен и лимит запросов не исчерпан. После замены ключа выполните docker compose restart backend feedback-api. Подробности ошибки можно найти в логах — команда ниже.

Первый запуск занимает много времени

При первом запуске Docker скачивает образы и зависимости. При первом поиске приложение также может скачать модели для обработки текста. Они нужны, даже если в архиве уже есть готовые эмбеддинги. Посмотрите логи: возможно, загрузка ещё идёт или прервалась из-за проблем с интернетом.

Порт занят или страница не открывается

Посмотрите состояние контейнеров командой docker compose ps. Порты 5173, 18000 и 18001 должны быть свободны до запуска. Кабинет открывается по адресу http://localhost:5173; открывать HTML-файл из папки frontend не нужно.

Логи сервисов 
docker compose logs --tail=100 backend feedback-api frontend
Остановить проект 
docker compose down
Запустить снова на PowerShell 
$env:CABINET_MODE='full'
docker compose up -d
Запустить снова на Linux / macOS 
export CABINET_MODE=full
docker compose up -d

И как это влияет на бизнес.

Новость становится полезной, когда управленцу понятно её влияние на конкретный бизнес. AlfaInsight связывает событие с данными вашей компании, добавляет аналитику банка и предлагает простые и понятные действия для того, кто принимает решение.

01

Кто за что отвечает

Четыре агента готовят разборы для вашего бизнеса. Два подбирают новости и оценивают последствия событий, третий параллельно изучает аналитику банка. Их выводы попадают в общую ленту, где четвёртый агент помогает вам обсудить карточку и уточнить детали.

Две ветки анализа → одна лента → обсуждение
Агент Данные и этапы обработки

Настраивает поиск под компанию

Агент изучает профиль вашей компании и подбирает запросы о спросе, расходах, поставщиках и финансировании. Затем проверяет их на реальных новостях, чтобы понять, какие события они находят и насколько подходят вашему бизнесу.

Что получает
Деятельность, масштаб, деловые связи вашей компании и используемые продукты банка. Эти факты помогают определить, какие изменения важны для вас.
Что делает
Он определяет каналы влияния на ваш бизнес, подбирает запросы и проверяет их на новостном корпусе перед передачей в поиск.
Что отдаёт
Запросы под вашу компанию и отчёт о проверенных темах, включая направления, по которым пока нет подходящих материалов.
note_business_modelprobefinish

Запросы сохраняются для следующих анализов вашей компании. Если агент не завершил подбор, поиск продолжится со стандартными запросами по её фактам, не прерывая остальные этапы.

Разбирается, что событие меняет для вас

Новость в вашей отрасли не всегда меняет положение вашей компании. Агент-судья проверяет её связь с деятельностью, платежами и планами бизнеса, затем оценивает последствия. Он учитывает вашу роль, чтобы разбор отвечал вашим задачам.

Что получает
Найденное событие, факты вашей компании, вашу роль и предварительную оценку релевантности, с которой агент начинает проверку влияния.
Что делает
Он читает источники, проверяет развитие события и обращается к данным компании и расчётам, чтобы объяснить важность новости для вас.
Что отдаёт
Решение о карточке: что событие меняет для вашего бизнеса, чем подтверждён вывод и каких сведений не хватает.
news_textsame_event_reportsfollow_up_news search_newssearch_bank_analyticscompany_factscompute

Автор карточки получает источники и расчёты судьи. До написания текста система отсеивает повторяющиеся выводы, чтобы одна рекомендация не занимала несколько мест в вашей ленте.

Находит выводы в аналитике банка

Агент связывает прогнозы ставки или курса с вашими кредитами, платежами и планами. Для этого он изучает текст, таблицы и графики в отчётах банка. Отдельная новость не нужна: вывод из самой аналитики тоже может попасть в вашу ленту.

Что получает
Профиль вашей компании, вашу роль и отчёты банка с текстом, таблицами и изображениями страниц — контекст для поиска и проверки выводов.
Что делает
Он находит нужные разделы, сравнивает выпуски и при необходимости открывает страницу, чтобы прочитать график или таблицу и связать их с вашей компанией.
Что отдаёт
Предложения для карточек с цитатами и расчётами, список изученных тем и открытые вопросы, для которых пока не хватило данных.
search_bank_analyticsread_pagelook_at_page compare_reportscompany_factsadd_candidatefinish

Код сверяет цитаты, числа и ссылки, затем возвращает агенту замечания. Дата отчёта и номер страницы сохраняются, чтобы вы могли проверить нужный фрагмент в исходном контексте.

Помогает разобраться в выводе

Обсудите вывод прямо в карточке: выделите фразу, попросите объяснить расчёт или уточните обстоятельства вашего бизнеса. Агент получит материалы и историю диалога, а при необходимости найдёт дополнительные сведения.

Что получает
Карточку, её источники, ваш вопрос и предыдущие сообщения, чтобы вам не приходилось заново объяснять контекст разговора.
Что делает
Он проверяет материалы и данные вашей компании, ищет недостающие сведения и отвечает со ссылками, по которым вы можете проверить вывод.
Что отдаёт
Ответ с источниками или уточняющий вопрос, если данных недостаточно. Вы видите и вывод, и границы доступной информации.
company_factscompany_cardcounterparties group_memberssearch_newssearch_bank_analytics

Ваши уточнения хранятся отдельно от исходных фактов. Явно сохранённые сведения и реакции на карточки могут учитываться при следующем анализе вашей компании.

02

Из чего состоит вывод

В карточке разделены событие, позиция аналитиков банка и вывод о влиянии на ваш бизнес. Вы можете проверить основания и решить, подходят ли предложенные действия вашей ситуации.

01 / Факты

Что произошло

Вы видите событие и его связь с фактами вашей компании. Рядом доступны статья, цитата или сведения из профиля, чтобы уточнить детали.

02 / Позиция банка

На что опираемся

Вы можете открыть отчёт банка, увидеть дату и нужную страницу. Так мнение аналитиков сохраняет контекст, а вы понимаете основания рекомендации.

03 / Вывод AI

Что это меняет

Система описывает риски и возможности для вашего бизнеса, затем предлагает действия с учётом вашей роли. Предположения отмечены отдельно, чтобы вы отличали факты от условий, которые ещё нужно проверить.

От карточки можно сразу
перейти к решению

Короткая версия инсайта помогает понять событие и его важность. Если тема касается ваших задач, откройте полный разбор, проверьте материалы и обсудите следующий шаг в той же карточке.

План действий

  • Посмотрите, что написано в самой новости или отчёте.
  • Проверьте, какие данные вашей компании учёл агент.
  • Задайте ему вопрос и сохраните то, что нужно учесть в следующем разборе.
03

Что сохраняется между запусками

Лента, материалы и обсуждения сохраняются, чтобы вы могли вернуться к ним в работе. Новый анализ использует подготовленные данные и кеш для совпавших запросов, не повторяя уже выполненную работу.

Готовые инсайты

Результаты анализов, краткие версии и предложенные вопросы остаются в вашей ленте. Вы можете вернуться к карточке и её материалам без нового прогона.

data/api/analyses · compact · suggested

Ответы моделей

Совпавший запрос может получить ответ из файлового кеша или Redis, сэкономив время и вызов модели. Новый вопрос или другой контекст могут потребовать обращения к API.

data/llm_cache · data/news/llm_cache

Материалы для поиска

Новости и распознанные отчёты подготовлены вместе с эмбеддингами — векторами для поиска по смыслу. Для вашего нового запроса модель рассчитывает отдельный вектор.

data/news · analytics · retrieval_v2

История и обратная связь

Ваши вопросы, ответы, реакции и сохранённые уточнения остаются в системе. Чат компании и обсуждение инсайта имеют отдельные истории, чтобы вы могли продолжить нужный разговор.

SQLite · пользователь · компания · роль
04

Что запускается в Docker

frontend

Ваш кабинет: здесь вы читаете ленту, открываете материалы и обсуждаете выводы для вашего бизнеса.

backend

Находит нужную вам компанию, загружает готовые результаты и принимает задачи на новый анализ.

feedback-api

Сохраняет ваши обсуждения и реакции, возвращает историю диалога и источники ответов агента.

redis

Предоставляет сервисам общий кеш для повторного использования ответов, в том числе после перезапуска.

можно проверить.

Когда вы принимаете решение для бизнеса, важно понимать, откуда взялся инсайт. В наших карточках всегда можно открыть источник, прочитать цитату в контексте и проверить расчёт. Поиск, содержание карточек и работу приложения мы проверяли отдельно.

01

Проверки по ходу анализа

Источники

Откуда взялось утверждение

Вы можете открыть новость, факт о компании или отчёт, на который ссылается карточка. Система проверяет ссылки и сохраняет хеши новостных текстов, чтобы их содержание можно было сверить.

Цитаты

Что сказано в оригинале

Раскройте цитату в карточке, затем перейдите к статье или странице отчёта. Система сверяет её с исходным текстом, а вы можете проверить, сохраняется ли смысл в контексте.

Расчёты

Как получилась цифра

Расчёт выполняет код, а формула, данные и допущения сохраняются в материалах разбора. Вы можете проследить, как получилась цифра; если она зависит от непроверенного условия, сценарий отмечается как гипотеза.

Лента

Что уже было сказано

Статьи об одном событии объединяются, а повторные выводы отсеиваются до написания карточек. Так вам проще просматривать ленту, где разные публикации не превращаются в одинаковые рекомендации.

Как проходит проверка карточки

Checker сверяет черновик с материалами, затем передаёт автору замечания. Автор может исправить текст один раз, без повторного checker. Если корректного вердикта нет, карточка может сохраниться с отметкой о несостоявшейся проверке. Ссылки и цитаты помогают вам проверить источники, но сами по себе не подтверждают полезность совета для бизнеса.

оцениваются отдельно

Новость становится полезной, когда из разбора понятно, что она меняет для вашей компании. Поэтому для готовых карточек предусмотрена отдельная оценка: как они отвечают вашим задачам и насколько хорошо объясняют вывод.

Что оцениваем

  • Относится ли вывод к вашей компании и вашим задачам?
  • Меняет ли он что-то в расходах, доходах или планах бизнеса?
  • Понятно ли, откуда взялись факты и расчёты?

04

Следующий шаг — обратная связь

Ваши реакции и обсуждения уже сохраняются. Дальше мы планируем использовать их для оценки и улучшения подбора, чтобы в ленте было больше событий и объяснений, которые помогают вам в работе.

  1. Проверить оценки вместе с экспертами

    Планируем сопоставить оценки модели с мнением специалистов, затем уточнить критерии и проверить порог качества на отдельной выборке. Так оценка будет ближе к тому, что вы считаете полезным.

  2. Понять, почему карточка не подошла

    Если карточка «не про нашу компанию», нужно проверить подбор; если в ней ошибка — содержание. Планируем разбирать причины ваших реакций, чтобы исправлять тот этап, где возникла проблема.

  3. Увидеть, какие разборы востребованы

    Планируем учитывать открытия, чтение и переходы к источникам вместе с положением карточки в ленте. Это покажет, к каким разборам вы возвращаетесь. Полный сбор этих событий пока не подключён.

  4. Контролировать скорость и стоимость анализа

    Планируем отслеживать время этапов, ошибки, стоимость вызовов и работу кеша, затем сообщать о сбоях через оповещения. Это поможет находить задержки и лишние расходы, контролируя время и стоимость анализа для вашего бизнеса.
